# 抓屏（Graphics Capture）局限性研究 · 交接材料

> 交接时间：2026-09-27
> 交接原因：用户要求把「抓屏方案的系统局限」作为一个独立课题交给新对话研究。
> 前置背景：项目 `F:\AI项目\冒险岛自动练级-公开版`（冒险岛怀旧服国服自动练级工具），
> issue #2 一路排查下来，暴露了抓屏这条路本身的若干限制。

---

## 一、这个课题要回答什么

**核心问题**：当前抓屏方案在哪些用户环境下会失效？有没有更稳/更兼容的替代方案？

具体要搞清楚的：

1. 当前方案（Windows 自带 Graphics Capture API）**对系统版本、显卡、驱动、虚拟机有什么硬要求**；
2. 哪些失败是"用户能自救"的（如最小化 → 还原窗口），哪些是**环境不满足、无解**的；
3. 失败时**能否提前检测出来**并明确告知用户（而不是让他对着"抓不到画面"干猜）；
4. 有没有值得换的替代方案（要权衡：是否需额外装驱动、是否兼容老系统、是否影响性能、是否违反项目"不碰游戏进程"的原则）。

## 二、当前实现（事实，别猜）

| 项 | 值 |
|---|---|
| 抓屏库 | `windows-capture` **2.0.1**（Rust 写的，Python 绑定） |
| 依赖 | 仅 `numpy` + `opencv-python`（**无驱动类依赖**） |
| 底层 API | Windows **自带的 Graphics Capture API**（Direct3D 11 抓帧） |
| 代码位置 | `src/input/GameWindowCapturor.py`（L10 导入、L66 创建、L71 启动线程） |
| 抓取方式 | **按 hwnd 抓窗口**（不是抓整个屏幕）—— 见该文件 L60 附近的踩坑注释：库对 `window_name` 做的是子串匹配，会误抓资源管理器 |
| 回调 | `on_frame_arrived`（存帧）、`on_closed`（关闭时打 warning） |

**已实测确认（2026-09-27，本机）**：无任何额外抓屏驱动的情况下，按 `window_hwnd` 捕获真实窗口（记事本）成功拿到 2560×1440 帧。→ **本方案不需要装驱动。**

## 三、已知道的限制（项目里已有记录，别重复踩）

1. **抓不到最小化的窗口** —— 一帧都不会来。项目已在 F4 启动前做检查并提示（`src/ui/ui.py` L2640 附近）。
2. **抓不到独占全屏的游戏** —— 这是本方案唯一与"驱动"无关的硬限制。项目要求游戏**必须窗口模式**（README、config 注释、用户版文档都写了）。
3. **窗口尺寸必须与配置一致** —— 否则裁剪失败、一帧拿不到（issue #2 首次报的就是这个）。
4. **系统版本要求**：Graphics Capture 需要 **Windows 10 1809 (build 17763) 以上**（待核实：2.0.1 这个库的实际最低版本要求）。
5. **显卡要求**：走 D3D11，老显卡/虚拟机/远程桌面环境可能不支持（**待实测核实**）。
6. **项目声明不支持虚拟机**（README 环境要求），但**没说明原因**——怀疑与抓屏有关，待确认。

## 四、待研究/待验证（这是交给新对话的主要工作）

### 需要实测或查证的

- [ ] `windows-capture` 2.0.1 的**官方最低系统要求**（查库文档/源码，别凭印象）
- [ ] 失败时的**具体错误类型**：库在系统不支持时抛什么异常？会不会静默不送帧？（静默失败最难查）
- [ ] 在**远程桌面 / 虚拟机 / 老显卡**上是否真的抓不到，能否用一个便宜的检测提前判断
- [ ] 游戏是 **Unity 重制版**（国服客户端），它对 Graphics Capture 是否友好（有项目是显式屏蔽该 API 的）
- [ ] 多屏 / 负坐标窗口（issue #2 用户就是多屏，窗口 rect 在负坐标区）是否有额外影响

### 可能需要产出的东西

- [ ] 一份**环境自检工具**：开跑前判断"你这台机器能不能抓屏"，不能就明确说原因 + 替代建议
- [ ] 失败时的**可读报错**（现在部分路径已有，被最小化那条就做得不错，可参照）
- [ ] 如果确实要换方案：**替代方案对比**（各自代价，尤其"要不要用户额外装东西"）

## 五、给新对话的提醒（重要）

1. **别在开发机上验证就下结论** —— 开发机是 Win11 + RTX 3070 + 缩放 100%，
   环境"太好"，很多限制在这里**根本复现不了**。要区分"我这儿能跑"和"用户能跑"。
2. **用户的实际环境**（从 issue #2 日志看）：多屏（窗口在负坐标区）、
   屏幕缩放与开发机不同（窗口尺寸两次都不一样：1282x707 / 1366x768 相关）、
   免安装包（**没有 Python**，所以任何"跑个 python 命令看看"的方案对他无效）。
3. **项目原则**：不读游戏内存、不碰游戏进程、优先不要求用户额外装东西。
   换方案时要守住这条，别引入内核驱动之类的新前置依赖。
4. **发布流程**：改了 `src/` 必须重新打包发版（只改源码不算已发布 —— 项目已因此翻车过一次）。
   发版流程见 README 的「发版：完整包 + 增量补丁」，或技能库
   `mem-skill-windows-pyinstaller-github-release-b57242b05ea1`。
5. **用户偏好**：对外文本（issue 回复、README、发布说明）用**简短白话**，
   技术细节留在 commit message 和代码注释里。
